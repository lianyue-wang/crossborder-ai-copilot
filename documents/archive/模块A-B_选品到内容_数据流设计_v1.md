## 0. 三条必须先纠正的判断（不改，后面全白做）

### 0.1 卖家精灵 API 你用不起，所以 MCP 是唯一路径 —— 但用法必须改

官方定价（2026-07 口径，来源：open.sellersprite.com/pricing/api 与第三方整理）：

| 接口 | 单价 | 额度 |
|---|---|---|
| 选产品 | **¥3,999/月** | 2 万次 |
| 查竞品 | ¥2,999/月 | 2 万次 |
| ASIN 竞品数据 | ¥6,988/月 | 2 万次 |
| ASIN 详情 | ¥988/月 | 5 万次 |
| 产品类目 | ¥680/月 | 5 万次 |

**API 是按接口分别卖的**，选品要跑通至少需要"选产品 + ASIN 详情"两个接口 = ¥4,987/月。个人开发者不可能承担。

MCP 套餐（同期口径）：

| 套餐 | 年费 | 每分钟 | 每月次数 |
|---|---|---|---|
| Basic | ¥990/年 | 40 | 4,000 |
| Pro | ¥1,990/年 | 60 | 10,000 |
| Max | ¥2,990/年 | 80 | 15,000 |

**同一个数据源，MCP 一年 990，API 一个月 4987。** 这就是为什么必须走 MCP。

**但用法要改**：

| 错误用法 | 正确用法 |
|---|---|
| 把 MCP 挂给 LLM，让模型自己决定调哪个工具 | **代码里写死工具名和参数**，直接调 MCP 的 `tools/call` |
| 每次调用都经过一次 LLM 决策 | 0 次 LLM 参与，纯 HTTP + JSON |
| 返回的是"AI 整理后的分析结果" | 拿到原始 JSON，Pydantic 校验成强类型对象 |
| 无法算成本、无法重试、无法降级 | 超时/重试/限流/缓存全部在客户端统一做 |

一句话：**把 MCP 当"便宜的 HTTP 数据接口"用，不当"给 AI 的工具"用。**

对外的解释（面试用）：MCP 是给 AI 客户端用的协议，我的系统里数据获取是确定性工作流——给定品类和筛选条件，调哪个接口是固定的，不需要模型决策。所以我在代码层直连 MCP 服务端，工具选择写死，只保留 Agent 需要自主探索时才把工具交给 LLM。

**`[待验证]`**：用 Python 官方 `mcp` SDK 的 streamable HTTP client 直连 `https://mcp.sellersprite.com/mcp`（header `secret-key`）能否在**非 AI 客户端**环境下正常工作。这是整个数据层的前提，必须第一步验，验不通就要退回 CLI 或自己包 HTTP。**排在 N2 开工第一件事，半天。**

### 0.2 AI 生成的图不能当主图 —— 这不是技术问题，是平台规则

亚马逊官方原文（来源：gs.amazon.cn/zhishi/article-241002、sellercentral G200421970）：

> 主图必须是**实际商品的专业照片**（不得是图形、插图、实物模型）

也就是说：**任何由扩散模型从零生成的产品图，规则上就不合规**，跟画得多好无关。

所以"用 AI 生成符合亚马逊要求的图片"这句话要拆开：

| 图位 | 能不能 AI 生成 | 正确做法 |
|---|---|---|
| **主图** | ❌ 不能 | 实拍图 → 代码抠图（rembg）→ 铺 RGB(255,255,255) 白底 → 代码合规校验 |
| 场景图/生活方式图（附图） | ⚠️ 只能生成**背景** | 真实产品抠图后合成到 AI 生成的场景里，产品像素必须来自实拍 |
| 卖点图/尺寸图/对比图 | ✅ 可以 | 真实产品图 + 代码排版文字（PIL），不靠模型画字 |
| A+ 模块图 | ✅ 可以 | 同上 |

**核心原则（一句话，面试可直接讲）：产品真实性不能交给生成模型。**

### 0.3 视频同理：AI 生成的是"氛围"，不是"产品"

你没做过视频，这里先把边界划清楚，否则会走错两周：

| 镜头类型 | 做法 |
|---|---|
| 产品本体镜头 | 实拍照片做 Ken Burns 推拉 / 或用现有短视频片段 |
| 场景氛围镜头 | AI 视频生成（Seedance 等）可以，产品不入镜 |
| 卖点字幕 / 动效 | 代码渲染（PIL/FFmpeg drawtext） |
| 配音 | TTS（已知文本，时间轴直接算，不用反解） |
| 转场 / 节奏 | FFmpeg |

AI 视频模型负责"这个画面感觉对"，不负责"这是我的产品"。

## 2. 重画后的数据流

```
【C 运营诊断】                     ┌──────────────────┐
 关键词方向                        │  卖家精灵 MCP     │
 产品建议（类目/价格带/卖点）──┐    │ （代码直连，写死）│
 差评痛点                      │    └────────┬─────────┘
                              ↓             │
                       ┌────────────────────┴──────────────┐
                       │  ① 选品筛（A 模块）                │
                       │  asin_list → 候选池                │
                       │  → asin_detail / prediction_sales   │
                       │  → category_top_list / demand_report│
                       │  → asin_review_list（痛点）         │
                       │  输出：评分卡 + 3 个候选品          │
                       └──────────────┬────────────────────┘
                                      ↓ 选中的 1 个 ASIN / 产品构想
                       ┌──────────────┴────────────────────┐
                       │  ② 词库搭建（新模块，独立）        │
                       │  来源：keyword_asin_list（竞品反查）│
                       │       keyword_related_list（扩展）  │
                       │       keyword_aba_list（官方热度）  │
                       │       keyword_batch_info（批量指标）│
                       │  处理：去重 → 打分 → 分层 → 打标   │
                       │  输出：分层词库（含每层用途）      │
                       └──────────────┬────────────────────┘
                                      ↓ 词库 + 竞品文案 + 产品信息
                       ┌──────────────┴────────────────────┐
                       │  ③ 文案（B-1）                     │
                       │  参考：asin_content_list（竞品五点）│
                       │  输出：标题/五点/A+/ST + 埋词报告  │
                       └──────────────┬────────────────────┘
                                      ↓
                       ┌──────────────┴────────────────────┐
                       │  ④ 图片（B-2）                     │
                       │  实拍图 → 抠图 → 白底 → 合规校验   │
                       │  竞品图（asin_content_list）→ 构图参考│
                       │  AI 只生成场景背景，产品像素真实   │
                       └──────────────┬────────────────────┘
                                      ↓
                       ┌──────────────┴────────────────────┐
                       │  ⑤ 视频（B-3）                     │
                       │  分镜脚本 → 实拍/生成素材 → TTS →  │
                       │  SRT（按文本算）→ FFmpeg 合成      │
                       └───────────────────────────────────┘
```

**新增的一块：② 词库搭建。** 这是你这轮需求里最有价值的增量，也是原方案漏掉的——原来"文案生成"是直接拿 ASIN 让 LLM 写，那是套壳；有了词库，文案才有依据、可复现、可评测。

## 3. 词库模块设计（新增，最关键的一块）

### 3.1 分层结构

| 层 | 来源工具 | 判定规则 | 用在哪 |
|---|---|---|---|
| **核心词**（2–3 个） | ABA 点击份额高 + 反查流量占比高 | 份额 top10% 且相关度高 | 标题前 60 字符 |
| **属性词** | `keyword_related_list` 中的属性修饰 + `category_ai_feature_list` | 含材质/尺寸/颜色/功能词 | 五点、Search Terms |
| **场景词/人群词** | `keyword_related_list` 长尾 | 含 for/gift/indoor/outdoor 等 | 五点、A+ |
| **长尾词** | `keyword_related_list` 低竞争高购买率 | 搜索量中低 + 购买率 top30% + 竞争度低 | 后台 ST、广告手动 |
| **否定词** | `keyword_conversion_analysis` 高点击低转化 | CVR 低于类目中位数 | 广告否词 |

### 3.2 哪部分用代码、哪部分用 LLM（这条决定可测性）

| 步骤 | 用什么 | 理由 |
|---|---|---|
| 去重、合并、拼写变体归并 | 代码 | 确定性 |
| 搜索量/购买率/竞争度打分排序 | 代码 | 纯数值 |
| 词库分层（按阈值切） | 代码 | 阈值可调、可复现 |
| **相关性判定**（这词跟我产品有关吗） | LLM + embedding 相似度 | 需要语义 |
| 属性/场景归类 | LLM（结构化输出） | 需要语义 |
| 否定词判定 | 规则 + LLM 双签 | 误杀代价高 |

**原则：数值算的归代码，语义判断的归 LLM。** 这样词库可复现、可评测；LLM 只影响"哪些词进来"，不影响"怎么排序"。

### 3.3 可评测指标（这个模块能做硬评测）

| 指标 | 怎么算 |
|---|---|
| 词库覆盖率 | 竞品 Top10 流量词中有多少进了你的词库（≥85%） |
| 埋词率 | 核心词是否 100% 出现在标题；属性词是否覆盖五点 ≥80% |
| 相关性准确率 | 人工抽检 50 词，判"该不该进库"（≥90%） |
| 否定词误杀率 | 被标否定的词里，人工判定其实相关的比例（≤5%） |
| 词库稳定性 | 同输入跑两次，词库 Jaccard 相似度（≥0.95） |

## 4. 图片合规模块（必须代码校验，不许 LLM 判断）

### 4.1 亚马逊官方硬指标（来源：gs.amazon.cn/zhishi/article-241002）

| 项 | 要求 | 能否代码校验 |
|---|---|---|
| 背景 | 纯白 RGB(255,255,255) | ✅ 检测四角 + 边缘像素 |
| 产品占比 | ≥85% | ✅ 前景 mask 面积 / 总面积 |
| 最长边 | ≥1600px，≤10000px | ✅ 读 EXIF |
| 格式 | JPEG/TIFF/PNG，首选 JPEG | ✅ |
| 主图禁项 | 无 logo/水印/文字/边框/色块/道具/多角度/多颜色 | ⚠️ OCR 查文字 + 人工确认 |
| 主图必须是实拍 | 不得是图形/插图/模型 | ❌ 代码判不了，靠流程约束 |

**前四项 100% 代码判定，做成一张 `compliance_report.json`。** 这就是"AI 生成 + 规则校验"的正确分工——不是让 LLM 说"我觉得合规"。

### 4.2 五点描述的硬约束（同样代码校验）

来源同上：总长度 <1000 字符、不得含 ®/™ 等特殊符号、不得含 HTML、不得含公司/促销/物流/邮箱信息、每条开头大写、结尾不加标点。
→ 写成 6 条正则/规则，生成后立即校验，不过就重写。
