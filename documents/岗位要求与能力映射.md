## 一、先看一个会改变策略的结论

**国内 FDE ≠ 国外 FDE。两者只有约 30% 重叠。**

| | 国外 FDE（Palantir / OpenAI / Anthropic / Google / Databricks） | 国内 FDE（联想 / 裕瑞 / 六联 / 码博 / 上海咨询型） |
|---|---|---|
| 岗位实质 | 把产品**装进客户业务**，写生产代码 + 定义抽象 | 把模型**装进客户机房**，部署 + 调优 + 交付 |
| 技术重心 | production software、**LLM evals**、agents、RAG、全栈 | **私有化部署、vLLM 推理优化、LoRA 微调、CUDA/CANN、GPU 环境、RoCE/IB 网络** |
| 核心动作 | discovery → 拆解 → 建 → 上线 → 迭代 | 一体机上架 → 环境初始化 → 压测 → 培训 → 验收 |
| 代码占比 | 高（OpenAI 明确"production-grade，全栈"） | 低（联想那条写"具备开发能力优先"，即加分项非必需） |
| 交付物 | tools and playbooks、runbooks、升级流程 | 交付文档、操作手册、客户培训 |
| 学历 | Google / Anthropic **接受 equivalent experience 代替本科** | 多数写本科；码博写**硕士**；联想那条未写学历硬门槛 |

**对你的直接影响**：如果按国外 FDE 的画像准备（eval、agent、全栈），投国内 FDE 会大面积错配——因为一半国内 FDE 岗要的是 CUDA 和 vLLM，不是 evals。

**反过来也算好消息**：国内 FDE 里有一支「应用交付型」分支，要的正是 RAG + Agent + 交付沟通，跟你主线完全同频。辅投就打这一支。

## 二、国外 FDE：真实要求（8 份在用 JD）

来源：heyarnoux.com/forward-deployed-engineer、howtoai.com/forward-deployed-engineer、fdejobs.com、dexity.com、routeswitchu.com（均为 2026 年 8–10 月抓取的在招 JD 汇总）

### 2.1 硬门槛

| 项 | 数据 |
|---|---|
| 经验 | Palantir **1+ 年**（有 new grad 岗，$135–145K）；Anthropic **4+**；OpenAI **5+**（FDSE 要 7+）；Google 5+ |
| 语言 | **Python 8/8**；TypeScript/JS 多数；SQL 常见 |
| 学历 | Google、Anthropic 明写**接受 equivalent experience 替代本科** |
| 出差 | Databricks 20% / Anthropic、Palantir 25% / OpenAI 50% / **Ramp 最高 75%** |
| 薪资（base） | Palantir $135–200K → Anthropic $280–320K；Google $174–252K + 15% bonus；OpenAI $185–325K + equity |

### 2.2 LLM 侧要求（原文口径）

- Anthropic：「Production experience with LLMs including **advanced prompt engineering, agent development, evaluation frameworks**, and deployment at scale」
- Google：「retrieval (RAG) pipelines built on vector databases」，偏好 **LangGraph / CrewAI / ADK**
- Ramp：要求"LLM systems that include **RAG, agents, monitoring, and evals**"

**注意：三家里三家都点了 evals。** 这不是加分项，是门槛项。

### 2.3 JD 八条里只有两条在讲写代码

OpenAI 旧金山 FDE 的「you might thrive in this role if you」共 8 条，2 条讲写软件，4 条讲性情（原文举例：「model calm and judgment when the stakes are high」「spot risks early and adjust without slowing down」）。Anthropic 10 条里 2 条技术，还明写「maintaining a **low ego**」。

**解读**：技术是地板，必须过；但地板之上考的全是判断力和沟通。这跟你现在准备的方向（技术深度）只对了一半。

### 2.4 面试形式（候选人反馈，非官方）

1. 动机筛
2. 生产风格 coding（不是 LeetCode）
3. **开放式拆解轮**：把模糊的企业问题拆成 data / schemas / APIs
4. 客户部署场景轮
5. 沟通密集型行为面
6. AI 实验室另加：evals 轮、retrieval 架构轮

> 第 3 条是重点：**考的是"给一个陌生业务，你怎么拆"，不是"你会不会写快排"。** 这恰好是你相对科班生的优势区（你有真实业务经验），但需要专门练。

### 2.5 一句话定义（Palantir 官方博客）

- 软件工程师：**one capability, many customers**
- FDE：**one customer, many capabilities**

### 3.1 结论：国内 FDE 分两支，只打一支

| 分支 | 特征 | 你要不要投 |
|---|---|---|
| **应用交付型** | RAG + Agent + 需求拆解 + 方案撰写 + 客户沟通 | ✅ **辅投就打这个**，跟你主线同频，边际成本低 |
| **部署优化型** | vLLM 调优 + LoRA 微调 + CUDA/CANN + GPU/网络 | ❌ **不投**。这些要 3–6 个月专门投入，且和 Agent 工程师主线不共享技能 |

**为应用交付型只需补三样**（合计 5–7 天，不新增里程碑）：

1. 私有化部署常识：本地用 Ollama 或 vLLM 起一个开源模型，跑通一次（2 天）——**不是学调优，是知道流程长什么样、能对话**
2. 方案撰写：出一份完整方案文档（PPT 或 PDF：现状 → 场景 → 架构图 → 实施路径 → 验收标准）（2–3 天）
3. Discovery 演练：模拟客户访谈，练"把模糊需求拆成技术方案"（1–2 天，M7 里做）

**明确不学**：CUDA/CANN、RoCE/IB、LoRA/QLoRA 微调、AI 硬件选型、TensorRT-LLM。

## 四、国内 Agent 工程师：5 份真实 JD，分三档

| 档 | 代表岗 | 薪资 | 硬门槛 | 筛人标准（JD 原文） |
|---|---|---|---|---|
| **A 高端（打不进）** | 上海 Agent 应用工程师 | **40–70K ×15** | **985/211 全日制硕士** + 5–10 年 | 任务规划、工具调用、上下文管理、记忆、多步骤工作流；**权限确认/沙箱/操作审计/敏感数据保护**；**效果评测、任务成功率、延迟、稳定性、成本评估体系** |
| **B 中端（主战场）** | 杭州 Agent 工程师 | **15–30K ×13** | **本科 + 2 年以上后端/AI 应用** | 单/多智能体、工具调用、工作流编排、**规划（ReAct / Plan&Execute）**、记忆与反思、Function Calling、结构化输出、RAG、**执行引擎/状态管理/任务拆解/调度/容错** |
| **B 中端** | 中移数智 Agent 研发 | 面议 | 硕士 3–5 年 | 售前支撑、PoC 验证、**成本评估**、项目交付 |
| **C 中低（要全栈）** | 北京拾光书房 Agent 开发 | **20–40K** | 本科 | Python/Node + **React/Vue/Next.js**、Prompt/RAG/向量检索/Agent、MySQL/PG/Redis、Linux/Git/Docker、LangChain/LlamaIndex/Dify/Flowise |
| **C 中低** | 猎聘 AI 应用开发（Agent 方向） | 未标 | 硕士 | 见下面 4.1，**这段是全文最重要的** |

### 4.1 三条 JD 原话，直接指出你 skill 现在的缺口

**原话 1**（猎聘，"我们重点关注"栏）：

> 「**Agent 系统思维**：能够从完整任务链路分析问题，关注上下文、工具调用、运行状态、异常处理和效果评测，而不只是完成模型 API 调用。」

**原话 2**（同上）：

> 「**分析与评测**：能够设计基本的对比实验，准确复现问题，并初步判断问题发生在**模型、检索、数据、工具还是工作流**环节。」

**原话 3**（上海 40–70K 岗）：

> 「建设 Agent **权限确认、沙箱、操作审计和敏感数据保护**机制；建立**效果评测、任务成功率、延迟、稳定性和成本**评估体系。」

三条指向同一件事：**市场筛人的标准不是"你会不会调 API"，是"Agent 出问题时你能不能定位到哪一层"。**

- 原话 2 那句「判断问题发生在模型、检索、数据、工具还是工作流」= **故障归因分层**。这是 Agent 工程最硬的能力，技能表里一个字都没有。
- 原话 1 那句「不只是完成模型 API 调用」= 明确排除"套壳"选手。
- 原话 3 的评测五项 + 权限四件套，跟主流 Agent 工程实践完全一致。

### 4.2 你的真实可投窗口

| 档 | 能不能投 | 依据 |
|---|---|---|
| A 高端 | ❌ | 985/211 硕士是硬门槛，绕不过 |
| **B 中端** | ✅ **主战场** | 杭州那条要求"本科 + 2 年以上后端/AI 应用开发"，你有 **2.5 年后端 + 项目**，能力项对得上；学历是唯一短板，用作品顶 |
| C 中低 | ⚠️ 部分可投 | 要 React 全栈的那类，你的 Streamlit 交付不够；但这类岗薪资反而高（20–40K），说明它们要的是"产品全栈"不是"Agent 专家"，取舍看你 |

**一个必须承认的现实**：国内正规 JD 几乎都写"本科及以上"。所以你的实际投递池不是"所有 B 类岗"，是：

1. **JD 未写学历门槛的**（如联想那条"具备开发能力优先"）
2. **0–20 人 / 天使轮 / 创业团队**（JD 写本科，实际看能力）
3. **内推 / 项目制 / 远程 / 外包转正**
4. **传统行业 AI 转型岗**（更看能不能干活）

这就是为什么"七件作品集"比"多学一个模块"重要：**学历是减分项，只能用可验证的交付物对冲，不能用知识点数量对冲。**
