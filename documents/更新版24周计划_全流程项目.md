## 三、项目方案对齐全流程（4阶段）

### 项目名称
**跨境电商AI全链路助手（Cross-border E-commerce AI Copilot）**

### 4阶段路线

| 阶段 | 周次 | 模块 | 代码量 | 产出 |
|------|------|------|--------|------|
| P1 | W1-6 | 选品+RAG知识库 | ~3,000行 | Demo1：关键词→选品报告 |
| P2 | W7-12 | 图文生成 | ~2,500行(累计5,500) | Demo2：ASIN→Listing文案+5张图 |
| P3 | W13-18 | 视频生成 | ~2,500行(累计8,000) | Demo3：产品图→15s带字幕配音视频 |
| P4 | W19-24 | 运营+整合+部署 | ~2,750行(累计10,750) | 在线产品+GitHub开源仓库 |

### 技术栈（精确到版本）

```
Python 3.11 + LangChain 0.2 + LangGraph 0.1 + FastAPI 0.110 + Streamlit 1.34
LLM: DeepSeek-V3/R1（主）+ Qwen-VL-Max（多模态审核）
图片: 通义万相 wanx2.1（API快速出图）+ ComfyUI（本地高质量/可控工作流，ControlNet+LoRA）
视频: 即梦Seedance（主）+ 可灵（备）
语音: CosyVoice 2 + faster-whisper + FFmpeg
选品数据: 卖家精灵（API/CSV导出，销量/趋势/竞品）+ Amazon SP-API + 爬虫（补充）
存储: PostgreSQL 16 + Chroma→Qdrant + Redis 7 + MinIO
部署: Docker + Docker Compose + 云服务器4C8G + Nginx反向代理 + LangSmith追踪
低代码: Dify（评论分析/客服FAQ工作流）
开发: Cursor主力 + GitHub Copilot辅助 + Git每日commit + Linux(WSL2/云服务器)开发环境
```

### 低代码 vs 手写代码边界

| 部分 | 实现方式 | 理由 |
|------|----------|------|
| 主路由+4业务Agent编排 | **手写LangGraph** | 核心链路，面试要讲状态机/工具调用 |
| RAG知识库 | **手写LangChain+Chroma** | 72%频率要求，必须手写体现深度 |
| 评论情感分析/客服FAQ | **Dify工作流** | 模板化，拖拽快，简历能写Dify |
| 数据采集(SP-API/爬虫) | **手写Python** | 反爬/限流/清洗 |
| 视频流水线 | **手写Python编排** | 异步/FFmpeg/失败重试 |
| 前端 | **Streamlit** | 一个人做不完React |

### 6.4 26道中小公司AI应用工程师面试题（不考算法）

**技术基础类（6题）**

1. **什么是RAG？为什么需要RAG？**
   - 答：检索增强生成，先从知识库检索相关文档，再和问题一起给大模型生成回答。解决大模型知识过时、不知道私有数据、幻觉问题。

2. **RAG完整流程？怎么优化效果？**
   - 答：加载→切分→Embedding→向量库→问题向量化→相似度检索TopK→拼接Prompt→生成。优化：调chunk_size(试过512效果好于256)、加overlap、加Rerank、优化检索策略、改进Prompt。

3. **什么是Agent？和Chatbot区别？**
   - 答：Agent能自主调用工具、根据观察决定下一步。Chatbot只能对话，Agent能做事（查数据库/调API/搜索）。我项目里用LangGraph StateGraph做主路由+4业务Agent。

4. **LangChain和Dify怎么选？**
   - 答：LangChain是代码框架，灵活但开发慢，适合核心编排；Dify是低代码，可视化拖拽快，适合模板化流程。我项目核心Agent编排手写LangGraph，评论分析/客服FAQ用Dify快速搭。

5. **大模型API调用注意什么？**
   - 答：①成本控制（token计费，控上下文）②超时重试 ③流式输出 ④错误处理 ⑤API Key安全 ⑥用LangSmith追踪调用链。

6. **向量数据库为什么用？Chroma和Qdrant区别？**
   - 答：存文本向量支持相似度检索，语义相近向量距离近。Chroma轻量嵌入式适合MVP，Qdrant性能好适合生产，我项目Chroma→Qdrant升级路径。

**项目深挖类（8题）**

7. **介绍一下你的项目？**
   - 用3分钟话术：跨境电商AI全链路助手，4层架构，4大Agent，多模型路由，业务Know-how沉淀。

8. **你这个项目里RAG效果怎么评估？**
   - 答：建了20个跨境电商常见问题的测试集，每个有标准答案。评估两个指标：①检索命中率——Top5结果里有没有包含答案的文档；②答案相关性——生成回答和标准答案的语义相似度。每次改chunk_size或Prompt后跑评估，用数据说话。chunk从256调到512，准确率从72%提到80%。另外用LangSmith追踪每次调用trace，能看到检索了哪些文档、花了多少token。

9. **项目里最大困难？怎么解决？**
   - 答：视频生成异步调度——Seedance耗时长需要Celery队列，且可能失败。做了三级降级：Seedance→可灵→图片轮播(Ken Burns)，配置切换。

10. **Agent工作流怎么设计的？**
    - 答：LangGraph StateGraph，主路由Agent做意图识别，分发到选品/图文/视频/运营Agent，用Checkpointer维护状态，有人工确认节点。

11. **爬虫被封怎么办？**
    - 答：控请求频率+UA轮换+延时+代理IP。MVP阶段用样本CSV+SP-API沙箱，爬虫作为能力点。

12. **数据库怎么设计的？**
    - 答：PostgreSQL三张核心表：products(ASIN/标题/价格/评分)、tasks(任务状态/类型)、generation_records(生成记录/模型/成本)。SQLAlchemy ORM。

13. **你用Cursor怎么开发的？**
    - 答：先写Pydantic契约再让Cursor生成实现，一次一个文件，报错贴完整stack trace，用.cursorrules固化规范。约70%代码AI生成，我负责设计和调优业务逻辑。

14. **再做一次怎么改进？**
    - 答：①加用户系统权限 ②加1688/速卖通数据源 ③RAG加Rerank ④Qdrant生产化 ⑤加更多视频模板。

15. **Function Calling怎么实现的？Agent怎么决定调哪个工具？**
    - 答：用LangChain的@tool装饰器定义工具函数，写清楚工具描述和参数schema，用bind_tools()绑定给LLM。LLM返回tool_call时包含要调用的工具名和参数，执行工具后把结果返回LLM继续推理。比如用户问"这个产品利润多少"，LLM识别需要调calculate_profit工具，传入price/cost参数，算完返回结果，LLM再组织成自然语言回答。选品Agent绑了4个工具：查卖家精灵、抓竞品、拉评论、算利润。

16. **流式输出怎么实现的？为什么要用流式？**
    - 答：后端用FastAPI的StreamingResponse返回SSE（Server-Sent Events），LLM调用用astream()逐字获取，每拿到一个chunk就yield给前端。前端用EventSource接收，逐字追加到页面。用流式是因为LLM生成完整内容可能要5-10秒，用户干等体验差，逐字返回感知响应时间从10秒降到1秒。Listing文案生成和选品报告都支持流式。

17. **多模型路由怎么做的？为什么不全部用最好的模型？**
    - 答：写了ModelRouter类，按任务类型选模型：文案生成/翻译用DeepSeek-V3（便宜，¥1/百万token），复杂推理用DeepSeek-R1，图片审核用Qwen-VL。每个任务配置主模型和备用模型列表，try-catch捕获异常后自动切下一个。不全用好模型是因为成本——R1比V3贵约10倍，文案生成V3效果足够。一个选品报告约¥0.05，全用R1要¥0.5，差10倍。

18. **异步任务队列怎么设计的？视频生成要等几分钟怎么办？**
    - 答：用Celery+Redis做任务队列。用户提交视频生成请求后，后端立即创建task_id返回不阻塞。Celery worker后台执行，任务状态存PostgreSQL（PENDING→RUNNING→SUCCESS/FAILED）。前端通过WebSocket实时接收进度推送（"正在生成第2/5个片段...40%"）。失败自动重试3次（指数退避），超时10分钟标记FAILED。用户可在任务历史查看所有记录，失败的可手动重试。

19. **Token成本怎么控制的？一个选品报告花多少钱？**
    - 答：封装LLMClient，每次调用自动记录model/prompt_tokens/completion_tokens，按模型单价算成本存数据库。控制手段：①上下文自动截断——超过4000token自动压缩历史；②Redis缓存——相同prompt结果缓存，重复调用不花钱；③批量处理——10条评论合并一次LLM调用；④模型路由——简单任务用便宜模型。一个选品报告约¥0.05，一条视频脚本约¥0.02，成本仪表盘能看日/月趋势和各模块占比。

20. **前端你用什么？能独立做前端吗？**
    - 答：主力用Streamlit快速出Demo，多页面/表单/表格/图表都能做。同时熟悉HTML/CSS/JavaScript基础，能用fetch调后端API渲染页面，做过独立的HTML前端不用框架。React了解基础（组件/props/state/useEffect），时间充裕时用React重写了首页展示全栈能力。中小公司前端要求"看得懂+能改"，我完全够用。
